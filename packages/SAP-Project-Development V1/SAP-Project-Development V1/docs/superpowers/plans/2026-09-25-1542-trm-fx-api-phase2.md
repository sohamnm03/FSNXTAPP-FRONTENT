# TRM FX transaction API (Phase 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish `ZFS_SB_TRMFX_O4_API`, an OData V4 Web API with create/read/update/delete and a
`Settle` action for FX transactions (product category 600), over the released `BAPI_FTR_FXT_DEALCREATE`
/ `DEALCHANGE` / `DEALGET` / `REVERSE` (reason 04) / `SETTLE` BAPIs.

**Architecture:** A clone of the interest rate instrument API (`ZFS_SB_TRMIRATE_O4_API`). One root
custom entity with an unmanaged, strict(2), non-draft BDEF. A query class lists deals from the
released `I_FinancialTransaction` (category 600) and fills each page row from `BAPI_FTR_FXT_DEALGET`.
The behavior pool calls each write BAPI `DESTINATION 'NONE'` and commits or rolls back in that session
(L-227). Nothing is built or tested locally. Every object is created and activated on DS4/100 over
MCP, and every task ends with a live PowerShell test against the published service.

**Tech Stack:** ABAP RAP (unmanaged custom entity, SAP_BASIS 758), CDS, OData V4, MCP servers
`adt-mcp` / `mcp-abap-abap-adt-api` / `sap-gui`, PowerShell 5.1.

**Spec:** `docs/superpowers/specs/2026-09-25-1410-trm-deal-apis-design.md`. Relevant sections:
§3 shared pattern, §5 API 2, §7 ActivityCategory and §9 Phase 2. Phases 3 (FX option) and 4 (LC) get
their own plans.

## Facts established while writing this plan (DS4/100, 2026-09-25)

- **Category 600 on DS4/100 holds two product types:** `40A` "FX Forward" (transaction types
  400 Forward, 410 Settlement, 500 Rollover, 600 Utilization, 700/710/720 Netting, 800 Cancellation)
  and `40B` "FX Spot" (401 Spot, 402 TOM, 403 Cash, 410, 500, 600, 700, 800). Both are plain FX
  transactions. No swap product type exists, so "no swaps" (spec §2) needs no extra filter.
- Company code 9990 has about 45 FX deals, all active (status 0). Deal `9990/0000040000258`
  (40A/400) is the payload source. Deal `9990/0000050000040` (40B/401) is a spot example.
- The BAPI signatures, read from the FM sources:
  - **`DEALCREATE`:** `FOREX` / `FOREXX` (`BAPI_FTR_CREATE_FXT(X)`), `GENERALCONTRACTDATA(X)`
    (`BAPI_FTR_CREATE(X)`), tables `PAYMENTDETAIL(X)`, `ADDFLOW(X)` and `RETURN`. Exports
    `FINANCIALTRANSACTION` and `COMPANYCODE`.
  - **`DEALCHANGE`:** `COMPANYCODE`, `FINANCIALTRANSACTION`, `FOREX` / `FOREXX`
    (`BAPI_FTR_CHANGE_FXT(X)`), `GENERALCONTRACTDATA(X)` (`BAPI_FTR_CHANGE(X)`), the same tables.
  - **`DEALGET`:** `RETURNFOREX` (`BAPI_FTR_GETDETAIL_FXT`), `RETURNGENERALCONTRACTDATA`
    (`BAPI_FTR_GETDETAIL`), tables `PAYMENTDETAIL`, `ADDFLOW` and `RETURN`.
  - **`REVERSE`:** `COMPANYCODE`, `FINANCIALTRANSACTION`, `REVERSALREASON`, table `RETURN`.
  - **`SETTLE`:** `COMPANYCODE`, `FINANCIALTRANSACTION`, table `RETURN`.
- `BAPI_FTR_CHANGE_FXT` allows only `BUY_AMOUNT`, `SELL_AMOUNT`, `VALUE_DATE`, `FORWARD_RATE`,
  `SPOT_RATE`, `SWAP_RATE` (plus NDF fields, out of scope). Currencies can be set on create only.
- Rate and amount data elements carry **no conversion exit**: `TB_KKURS`, `TB_KKASSA`, `TB_KSWAP`
  (DEC 13,9), `BAPITB_BZBETR` (DEC 23,4). They can be used as element types unchanged, unlike EXCRT in
  Phase 1 (L-575 context).
- `BAPI_FTR_GETDETAIL` has no product category field. A GET by key goes through the query class, whose
  CTE already restricts rows to category 600, so a non-FX deal answers 404 (tested in Task 2).

## Deviation from the spec for the human to approve

Spec §5 lists `BuyCurrency`/`SellCurrency` but not the quotation. This plan also exposes
**`LeadCurrency` and `FollowCurrency`** (create-only, from `BAPI_FTR_CREATE_FXT`). Without them a
caller cannot say which way `SpotRate`/`ForwardRate` are quoted. If the human declines, delete the two
elements, their four mapping lines in Task 3 and their `readonly : update` entries. Nothing else
depends on them.

## Review Focus

1. **POST without `SellAmount`:** the caller gives the buy amount and the rates and expects the BAPI
   to compute the sell side. The 201 response must show a non-zero `SellAmount`, read back after the
   commit, not an echo of the input. Pinned by check `W1` in `fx-crud.ps1` (Task 3).
2. **A POST that fails after the BAPI committed (L-568):** the caller sees an error while a deal
   exists. Pinned by check `W0`/`W9` in `fx-crud.ps1`: the 9990 deal count is taken before the POST and
   compared after the reversal, allowing exactly +1 (the reversed test deal stays listed).
3. **GET by key for a non-FX deal** (the IRATE deal `1000/160539`) must answer 404, not a row with
   blank FX fields. Pinned by check `R3` (Task 2).
4. **`$filter` on a field only DEALGET supplies** (`BuyAmount gt 0`) must be refused cleanly with a
   4xx/5xx, not dump or silently ignore the filter. Pinned by check `R4` (Task 2).
5. **DELETE on a settled deal:** the first DELETE reverses only the settlement, and the deal must still
   read as active. Pinned by check `W8`, which asserts that `ActiveStatus` reaches `3` only after the
   loop and records how many DELETEs it took (Task 3).

- [ ] **Step 2: Write the acceptance script**

`scripts/trm-deal-api-tests/fx-crud.ps1`:

```powershell
# Live acceptance test for ZFS_SB_TRMFX_O4_API (Phase 2) on DS4/100, company code 9990.
# Usage: powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\trm-deal-api-tests\fx-crud.ps1 `
#          -EvidenceDir <dir> [-SourceDeal 40000258] [-Stage read|all]
#   read = read-only checks R1-R5 (Task 2); all = R1-R5 + the write lifecycle W0-W9 (Task 3).
# Exit 0 = every check GREEN, 1 = at least one RED. Writes <EvidenceDir>\fx-crud-log.txt.
param([string]$EvidenceDir, [string]$SourceDeal = '40000258', [ValidateSet('read', 'all')][string]$Stage = 'all')
. (Join-Path $PSScriptRoot 'trm-odata.ps1')
$svc  = 'zfs_sb_trmfx_o4_api/srvd_a2x/sap/zfs_sd_trmfx/0001'
$item = 'zfs_sb_trmdealitem_o4_api/srvd_a2x/sap/zfs_sd_trmdealitem/0001'
$ns   = 'com.sap.gateway.srvd_a2x.zfs_sd_trmfx.v0001'
New-Item -ItemType Directory -Force $EvidenceDir | Out-Null
$log  = Join-Path $EvidenceDir 'fx-crud-log.txt'
$script:ok = $true
function Check([string]$Name, [bool]$Pass, [string]$Detail) {
  Write-Host ("$Name $Detail -> " + $(if ($Pass) { 'GREEN' } else { 'RED' }))
  if (-not $Pass) { $script:ok = $false }
}
function Json($r) { if ($r.Content) { try { return $r.Content | ConvertFrom-Json } catch { } } return $null }
function Key([string]$Company, [string]$Deal) { "FxTransaction(CompanyCode='$Company',FinancialTransaction='$Deal')" }

# ---- read-only checks -------------------------------------------------------------------------
$r = Invoke-Trm $svc 'R1-list' GET "FxTransaction?`$filter=CompanyCode eq '9990'&`$count=true&`$top=5" $null $log
$j = Json $r
Check 'R1 list 9990' (($r.Status -eq 200) -and ($j.'@odata.count' -ge 30) -and (@($j.value).Count -le 5)) "status $($r.Status) count $($j.'@odata.count') page $(@($j.value).Count)"

$r = Invoke-Trm $svc 'R2-source' GET (Key '9990' $SourceDeal) $null $log
$src = Json $r
Check 'R2 source deal' (($r.Status -eq 200) -and $src.BuyCurrency -and $src.SellCurrency -and $src.ActivityCategory) "status $($r.Status) $($src.BuyCurrency)/$($src.SellCurrency) fwd $($src.ForwardRate) cat $($src.ActivityCategory)"

$r = Invoke-Trm $svc 'R3-non-fx-deal' GET (Key '1000' '160539') $null $log
Check 'R3 IRATE deal via FX API' ($r.Status -eq 404) "status $($r.Status)"

$r = Invoke-Trm $svc 'R4-bapi-only-filter' GET "FxTransaction?`$filter=BuyAmount gt 0" $null $log
Check 'R4 filter on BuyAmount refused' ($r.Status -ge 400) "status $($r.Status)"

$r = Invoke-Trm $svc 'R5-spot-filter' GET "FxTransaction?`$filter=CompanyCode eq '9990' and ProductType eq '40B'&`$count=true" $null $log
$j = Json $r
$allSpot = (@($j.value | Where-Object { $_.ProductType -ne '40B' }).Count -eq 0)
Check 'R5 ProductType eq 40B' (($r.Status -eq 200) -and ($j.'@odata.count' -ge 1) -and $allSpot) "status $($r.Status) count $($j.'@odata.count')"

if ($Stage -eq 'read') { if ($script:ok) { 'READ GREEN'; exit 0 } else { 'READ RED'; exit 1 } }
if (-not $src) { 'no source deal - cannot build the POST body'; exit 1 }

# ---- write lifecycle --------------------------------------------------------------------------
$r = Invoke-Trm $svc 'W0-count-before' GET "FxTransaction?`$filter=CompanyCode eq '9990'&`$count=true&`$top=0" $null $log
$countBefore = (Json $r).'@odata.count'

# Value date ~3 months out, moved off the weekend. The rates are the source deal's own consistent triple.
$vd = (Get-Date).AddDays(91)
while ($vd.DayOfWeek -in 'Saturday', 'Sunday') { $vd = $vd.AddDays(1) }
$body = [ordered]@{
  CompanyCode = '9990'; ProductType = '40A'; TransactionType = '400'; Partner = $src.Partner
  ContractDate = (Get-Date -Format 'yyyy-MM-dd'); BuyCurrency = $src.BuyCurrency; SellCurrency = $src.SellCurrency
  BuyAmount = 100000; ValueDate = $vd.ToString('yyyy-MM-dd')
}
if ($src.LeadCurrency)   { $body.LeadCurrency   = $src.LeadCurrency }
if ($src.FollowCurrency) { $body.FollowCurrency = $src.FollowCurrency }
if ($src.ValuationClass) { $body.ValuationClass = $src.ValuationClass }
if ($src.Portfolio)      { $body.Portfolio      = $src.Portfolio }
foreach ($f in 'SpotRate', 'SwapRate', 'ForwardRate') { if ([double]$src.$f -ne 0) { $body[$f] = $src.$f } }
$r = Invoke-Trm $svc 'W1-create' POST 'FxTransaction' ($body | ConvertTo-Json -Compress) $log
$new = Json $r
Check 'W1 create' (($r.Status -eq 201) -and $new.FinancialTransaction -and ([double]$new.SellAmount -ne 0) -and ($new.ActivityCategory -eq '10')) "status $($r.Status) deal $($new.FinancialTransaction) sell $($new.SellAmount) cat $($new.ActivityCategory)"
if ($r.Status -ne 201) { 'WRITE RED (create failed)'; exit 1 }
$deal = $new.FinancialTransaction
Write-Host "TEST DEAL: 9990/$deal"

$r = Invoke-Trm $svc 'W2-read' GET (Key '9990' $deal) $null $log
Check 'W2 read' (($r.Status -eq 200) -and ([double](Json $r).BuyAmount -eq 100000)) "status $($r.Status) buy $((Json $r).BuyAmount)"

$r = Invoke-Trm $svc 'W3-patch' PATCH (Key '9990' $deal) '{"BuyAmount":150000}' $log
$g = Json (Invoke-Trm $svc 'W3-read-after-patch' GET (Key '9990' $deal) $null $log)
Check 'W3 patch BuyAmount' (($r.Status -eq 200) -and ([double]$g.BuyAmount -eq 150000)) "status $($r.Status) buy $($g.BuyAmount) sell $($g.SellAmount)"

# Product independence (spec §9 Phase 2): a payment detail through API 1 on the FX deal.
$pdFilter = "PaymentDetail?`$filter=CompanyCode eq '9990' and FinancialTransaction eq '$deal'"
$existing = @((Json (Invoke-Trm $item 'W4-paydet-list' GET $pdFilter $null $log)).value)
$eff = $vd.ToString('yyyyMMdd')
$pick = @(@{ Dir = '+'; Cur = $g.BuyCurrency }, @{ Dir = '-'; Cur = $g.SellCurrency }) |
        Where-Object { $c = $_; -not ($existing | Where-Object { $_.Direction -eq $c.Dir -and $_.PaymentCurrency -eq $c.Cur }) } |
        Select-Object -First 1
if ($pick) {
  $pd = [ordered]@{ CompanyCode = '9990'; FinancialTransaction = $deal; Direction = $pick.Dir; EffectiveDate = $eff
                    FlowType = ''; PaymentCurrency = $pick.Cur; Payer = $g.Partner; PaymentActivity = $true }
  $r = Invoke-Trm $item 'W4-paydet-create' POST 'PaymentDetail' ($pd | ConvertTo-Json -Compress) $log
  $pdKey = "PaymentDetail(CompanyCode='9990',FinancialTransaction='$deal',Direction='$($pick.Dir)',EffectiveDate='$eff',FlowType='',PaymentCurrency='$($pick.Cur)')"
  $d = Invoke-Trm $item 'W4-paydet-delete' DELETE $pdKey $null $log
  Check 'W4 payment detail via API 1' (($r.Status -eq 201) -and ($d.Status -eq 204)) "create $($r.Status) delete $($d.Status)"
} else {
  $row = $existing[0]
  $pdKey = "PaymentDetail(CompanyCode='9990',FinancialTransaction='$deal',Direction='$($row.Direction)',EffectiveDate='$($row.EffectiveDate)',FlowType='$($row.FlowType)',PaymentCurrency='$($row.PaymentCurrency)')"
  $flip = -not [bool]$row.IndividualPayment
  $p1 = Invoke-Trm $item 'W4-paydet-patch' PATCH $pdKey ('{"IndividualPayment":' + "$flip".ToLower() + '}') $log
  $p2 = Invoke-Trm $item 'W4-paydet-restore' PATCH $pdKey ('{"IndividualPayment":' + "$(-not $flip)".ToLower() + '}') $log
  Check 'W4 payment detail via API 1 (patch round trip)' (($p1.Status -eq 200) -and ($p2.Status -eq 200)) "patch $($p1.Status) restore $($p2.Status)"
}

$r = Invoke-Trm $svc 'W5-settle' POST ((Key '9990' $deal) + "/$ns.Settle") '{}' $log
$g = Json (Invoke-Trm $svc 'W5-read-after-settle' GET (Key '9990' $deal) $null $log)
Check 'W5 settle' (($r.Status -eq 200) -and ($g.ActivityCategory -ne '10')) "status $($r.Status) cat $($g.ActivityCategory) active $($g.ActiveStatus)"

$r = Invoke-Trm $svc 'W6-settle-again' POST ((Key '9990' $deal) + "/$ns.Settle") '{}' $log
Check 'W6 second settle refused' ($r.Status -ge 400) "status $($r.Status)"

$r = Invoke-Trm $svc 'W7-patch-readonly' PATCH (Key '9990' $deal) '{"BuyCurrency":"EUR"}' $log
Check 'W7 PATCH of a create-only field refused' ($r.Status -ge 400) "status $($r.Status)"

$n = 0; $status = ''
while ($n -lt 3 -and $status -ne '3') {
  $n++
  $d = Invoke-Trm $svc "W8-reverse-$n" DELETE (Key '9990' $deal) $null $log
  $status = [string](Json (Invoke-Trm $svc "W8-read-$n" GET (Key '9990' $deal) $null $log)).ActiveStatus
  Write-Host "DELETE $n -> $($d.Status), ActiveStatus $status"
}
Check 'W8 reversed' ($status -eq '3') "after $n DELETE(s)"

$r = Invoke-Trm $svc 'W9-count-after' GET "FxTransaction?`$filter=CompanyCode eq '9990'&`$count=true&`$top=0" $null $log
$countAfter = (Json $r).'@odata.count'
Check 'W9 exactly one deal added' ($countAfter -eq $countBefore + 1) "before $countBefore after $countAfter"

if ($script:ok) { 'SUITE GREEN'; exit 0 } else { 'SUITE RED'; exit 1 }
```

  PUBLIC SECTION.

    TYPES ty_deal   TYPE zfs_ce_trmfxtp.
    TYPES tt_deal   TYPE STANDARD TABLE OF ty_deal WITH EMPTY KEY.

CLASS zcl_fs_trm_fx_query IMPLEMENTATION.
  METHOD if_rap_query_provider~select.
    DATA lt_deals TYPE tt_deal.

    DATA(lv_where) = io_request->get_filter( )->get_as_sql_string( ).
    DATA(lv_order) = build_order_by( io_request->get_sort_elements( ) ).
    DATA(lv_offset) = io_request->get_paging( )->get_offset( ).
    DATA(lv_top) = io_request->get_paging( )->get_page_size( ).
    IF lv_top = if_rap_query_paging=>page_size_unlimited.
      lv_top = 0.
    ENDIF.

    " Header fields come from the released I_FinancialTransaction, restricted to
    " product category 600 (FX transactions: 40A forward, 40B spot on this system).
    " The CTE renames them to the entity's element names so the OData $filter/$orderby
    " string applies as is.
    TRY.
        IF io_request->is_total_numb_of_rec_requested( ).
          WITH +deals AS (
            SELECT FROM i_financialtransaction
              FIELDS CompanyCode,
                     FinancialTransaction,
                     FinancialInstrumentProductType AS ProductType,
                     FinancialInstrTransactionType  AS TransactionType,
                     Counterparty                   AS Partner,
                     TreasuryValuationClass         AS ValuationClass,
                     Portfolio,
                     FinancialInstrumentStatus      AS ActiveStatus
              WHERE FinancialInstrProductCategory = '600' )
          SELECT FROM +deals
            FIELDS COUNT( * )
            WHERE (lv_where)
            INTO @DATA(lv_count).
          io_response->set_total_number_of_records( lv_count ).
        ENDIF.

        IF io_request->is_data_requested( ).
          WITH +deals AS (
            SELECT FROM i_financialtransaction
              FIELDS CompanyCode,
                     FinancialTransaction,
                     FinancialInstrumentProductType AS ProductType,
                     FinancialInstrTransactionType  AS TransactionType,
                     Counterparty                   AS Partner,
                     TreasuryValuationClass         AS ValuationClass,
                     Portfolio,
                     FinancialInstrumentStatus      AS ActiveStatus
              WHERE FinancialInstrProductCategory = '600' )
          SELECT FROM +deals
            FIELDS *
            WHERE (lv_where)
            ORDER BY (lv_order)
            INTO CORRESPONDING FIELDS OF TABLE @lt_deals
            OFFSET @lv_offset
            UP TO @lv_top ROWS.
        ENDIF.

      CATCH cx_sy_dynamic_osql_error INTO DATA(lx_sql).
        " A $filter/$orderby on a field that only the BAPI supplies (amounts, rates,
        " currencies, ActivityCategory, ...) is not a database column of the CTE.
        RAISE EXCEPTION TYPE cx_rap_query_cond
          EXPORTING previous = lx_sql.
    ENDTRY.

    IF io_request->is_data_requested( ) = abap_false.
      RETURN.
    ENDIF.

    " Enrich each row on the page with the fields only BAPI_FTR_FXT_DEALGET returns.
    LOOP AT lt_deals ASSIGNING FIELD-SYMBOL(<ls_deal>).
      read_deal( EXPORTING iv_company_code = <ls_deal>-CompanyCode
                           iv_transaction  = <ls_deal>-FinancialTransaction
                 IMPORTING es_deal         = DATA(ls_detail) ).
      IF ls_detail IS NOT INITIAL.
        <ls_deal> = ls_detail.
      ENDIF.
    ENDLOOP.

    io_response->set_data( lt_deals ).
  ENDMETHOD.

  METHOD build_order_by.
    LOOP AT it_sort INTO DATA(ls_sort).
      rv_order = COND #( WHEN rv_order IS INITIAL
                         THEN |{ ls_sort-element_name }|
                         ELSE |{ rv_order }, { ls_sort-element_name }| ).
      IF ls_sort-descending = abap_true.
        rv_order = |{ rv_order } DESCENDING|.
      ENDIF.
    ENDLOOP.
    IF rv_order IS INITIAL.
      rv_order = c_default_order.
    ENDIF.
  ENDMETHOD.

  METHOD read_deal.
    DATA ls_general TYPE bapi_ftr_getdetail.
    DATA ls_forex   TYPE bapi_ftr_getdetail_fxt.
    DATA lt_paydet  TYPE STANDARD TABLE OF bapi_ftr_paydet.
    DATA lt_addflow TYPE STANDARD TABLE OF bapi_ftr_flow.
    DATA lv_msgtxt  TYPE c LENGTH 220.

    CLEAR: es_deal,
           et_return.

    " RETURN keeps the default table key: the FTR BAPIs hand it on to a subroutine
    " typed that way, and an EMPTY KEY table dumps (L-568).
    IF iv_via_rfc = abap_true.
      " Behaviour-pool callers: the BO's writes run in the DESTINATION 'NONE' session
      " (L-227), so the read is made there too.
      CALL FUNCTION 'BAPI_FTR_FXT_DEALGET'
        DESTINATION 'NONE'
        EXPORTING  companycode               = iv_company_code
                   financialtransaction      = iv_transaction
        IMPORTING  returnforex               = ls_forex
                   returngeneralcontractdata = ls_general
        TABLES     paymentdetail             = lt_paydet
                   addflow                   = lt_addflow
                   return                    = et_return
        EXCEPTIONS system_failure            = 1 MESSAGE lv_msgtxt
                   communication_failure     = 2 MESSAGE lv_msgtxt
                   OTHERS                    = 3.
      IF sy-subrc <> 0.
        APPEND VALUE #( type       = 'E'
                        id         = 'ZFS_TRM_MSG'
                        number     = '020'
                        message_v1 = 'BAPI_FTR_FXT_DEALGET'
                        message_v2 = lv_msgtxt ) TO et_return.
        RETURN.
      ENDIF.
    ELSE.
      CALL FUNCTION 'BAPI_FTR_FXT_DEALGET'
        EXPORTING companycode               = iv_company_code
                  financialtransaction      = iv_transaction
        IMPORTING returnforex               = ls_forex
                  returngeneralcontractdata = ls_general
        TABLES    paymentdetail             = lt_paydet
                  addflow                   = lt_addflow
                  return                    = et_return.
    ENDIF.

    IF line_exists( et_return[ type = 'E' ] ) OR line_exists( et_return[ type = 'A' ] ).
      RETURN.
    ENDIF.

    es_deal = VALUE #( CompanyCode          = ls_general-company_code
                       FinancialTransaction = ls_general-transaction
                       ProductType          = ls_general-product_type
                       TransactionType      = ls_general-transaction_type
                       Partner              = ls_general-partner
                       ContractDate         = ls_general-contract_date
                       ValuationClass       = ls_general-valuation_class
                       Portfolio            = ls_general-portfolio
                       ActiveStatus         = ls_general-active_status_transaction
                       ActivityCategory     = ls_general-activity_cat
                       BuyCurrency          = ls_forex-buy_currency
                       SellCurrency         = ls_forex-sell_currency
                       LeadCurrency         = ls_forex-lead_currency
                       FollowCurrency       = ls_forex-follow_currency
                       BuyAmount            = ls_forex-buy_amount
                       SellAmount           = ls_forex-sell_amount
                       ValueDate            = ls_forex-value_date
                       SpotRate             = ls_forex-spot_rate
                       SwapRate             = ls_forex-swap_rate
                       ForwardRate          = ls_forex-forward_rate ).
  ENDMETHOD.
ENDCLASS.

        ls_forexx-spot_rate = abap_true.
      ENDIF.
      IF ls_entity-%control-SwapRate = if_abap_behv=>mk-on.
        ls_forex-swap_rate = ls_entity-SwapRate.
        ls_forexx-swap_rate = abap_true.
      ENDIF.
      IF ls_entity-%control-ForwardRate = if_abap_behv=>mk-on.
        ls_forex-forward_rate = ls_entity-ForwardRate.
        ls_forexx-forward_rate = abap_true.
      ENDIF.

      " The *_COMPLETE_INDICATOR flags stay blank: the empty payment-detail/flow tables
      " then mean "no change", not "replace with nothing" (L-566).
      CALL FUNCTION 'BAPI_FTR_FXT_DEALCHANGE'
        DESTINATION 'NONE'
        EXPORTING  companycode           = ls_entity-CompanyCode
                   financialtransaction  = ls_entity-FinancialTransaction
                   forex                 = ls_forex
                   forexx                = ls_forexx
                   generalcontractdata   = ls_general
                   generalcontractdatax  = ls_generalx
        TABLES     paymentdetail         = lt_paydet
                   paymentdetailx        = lt_paydetx
                   addflow               = lt_addflow
                   addflowx              = lt_addflowx
                   return                = lt_return
        EXCEPTIONS system_failure        = 1 MESSAGE lv_msgtxt
                   communication_failure = 2 MESSAGE lv_msgtxt
                   OTHERS                = 3.
      IF sy-subrc <> 0.
        APPEND rfc_error( iv_function = 'BAPI_FTR_FXT_DEALCHANGE'
                          iv_text     = lv_msgtxt ) TO lt_return.
      ELSE.
        APPEND LINES OF end_luw( xsdbool( has_error( lt_return ) = abap_false ) ) TO lt_return.
      ENDIF.

      IF has_error( lt_return ) = abap_true.
        APPEND VALUE #( %tky        = ls_entity-%tky
                        %fail-cause = if_abap_behv=>cause-unspecific ) TO failed-trmfx.
      ENDIF.
      LOOP AT lt_return INTO DATA(ls_return).
        APPEND VALUE #( %tky = ls_entity-%tky
                        %msg = to_message( ls_return ) ) TO reported-trmfx.
      ENDLOOP.
    ENDLOOP.
  ENDMETHOD.

  METHOD delete.
    DATA lt_return TYPE tt_return.
    DATA lv_msgtxt TYPE c LENGTH 220.

    LOOP AT keys INTO DATA(ls_key).
      CLEAR: lt_return, lv_msgtxt.

      " A financial transaction is never physically deleted: DELETE reverses its latest
      " activity with reason 04 "Other reasons" (human decision, L-565/L-571).
      CALL FUNCTION 'BAPI_FTR_FXT_REVERSE'
        DESTINATION 'NONE'
        EXPORTING  companycode           = ls_key-CompanyCode
                   financialtransaction  = ls_key-FinancialTransaction
                   reversalreason        = c_reversal_reason
        TABLES     return                = lt_return
        EXCEPTIONS system_failure        = 1 MESSAGE lv_msgtxt
                   communication_failure = 2 MESSAGE lv_msgtxt
                   OTHERS                = 3.
      IF sy-subrc <> 0.
        APPEND rfc_error( iv_function = 'BAPI_FTR_FXT_REVERSE'
                          iv_text     = lv_msgtxt ) TO lt_return.
      ELSE.
        APPEND LINES OF end_luw( xsdbool( has_error( lt_return ) = abap_false ) ) TO lt_return.
      ENDIF.

      IF has_error( lt_return ) = abap_true.
        APPEND VALUE #( %tky        = ls_key-%tky
                        %fail-cause = if_abap_behv=>cause-unspecific ) TO failed-trmfx.
      ENDIF.
      LOOP AT lt_return INTO DATA(ls_return).
        APPEND VALUE #( %tky = ls_key-%tky
                        %msg = to_message( ls_return ) ) TO reported-trmfx.
      ENDLOOP.
    ENDLOOP.
  ENDMETHOD.

  METHOD settle.
    DATA lt_return TYPE tt_return.
    DATA lv_msgtxt TYPE c LENGTH 220.

    LOOP AT keys INTO DATA(ls_key).
      CLEAR: lt_return, lv_msgtxt.

      " No precondition checks of our own: the BAPI refuses a deal that cannot be
      " settled and its message is passed through (L-570).
      CALL FUNCTION 'BAPI_FTR_FXT_SETTLE'
        DESTINATION 'NONE'
        EXPORTING  companycode           = ls_key-CompanyCode
                   financialtransaction  = ls_key-FinancialTransaction
        TABLES     return                = lt_return
        EXCEPTIONS system_failure        = 1 MESSAGE lv_msgtxt
                   communication_failure = 2 MESSAGE lv_msgtxt
                   OTHERS                = 3.
      IF sy-subrc <> 0.
        APPEND rfc_error( iv_function = 'BAPI_FTR_FXT_SETTLE'
                          iv_text     = lv_msgtxt ) TO lt_return.
      ELSE.
        APPEND LINES OF end_luw( xsdbool( has_error( lt_return ) = abap_false ) ) TO lt_return.
      ENDIF.

      LOOP AT lt_return INTO DATA(ls_return).
        APPEND VALUE #( %tky = ls_key-%tky
                        %msg = to_message( ls_return ) ) TO reported-trmfx.
      ENDLOOP.
      IF has_error( lt_return ) = abap_true.
        APPEND VALUE #( %tky        = ls_key-%tky
                        %fail-cause = if_abap_behv=>cause-unspecific ) TO failed-trmfx.
        CONTINUE.
      ENDIF.

      zcl_fs_trm_fx_query=>read_deal( EXPORTING iv_company_code = ls_key-CompanyCode
                                                iv_transaction  = ls_key-FinancialTransaction
                                                iv_via_rfc      = abap_true
                                      IMPORTING es_deal         = DATA(ls_deal) ).
      APPEND VALUE #( %tky   = ls_key-%tky
                      %param = CORRESPONDING #( ls_deal ) ) TO result.
    ENDLOOP.
  ENDMETHOD.

  METHOD read.
    LOOP AT keys INTO DATA(ls_key).
      zcl_fs_trm_fx_query=>read_deal( EXPORTING iv_company_code = ls_key-CompanyCode
                                                iv_transaction  = ls_key-FinancialTransaction
                                                iv_via_rfc      = abap_true
                                      IMPORTING es_deal         = DATA(ls_deal)
                                                et_return       = DATA(lt_return) ).
      IF has_error( lt_return ) = abap_true OR ls_deal IS INITIAL.
        APPEND VALUE #( %tky        = ls_key-%tky
                        %fail-cause = if_abap_behv=>cause-not_found ) TO failed-trmfx.
        CONTINUE.
      ENDIF.
      APPEND CORRESPONDING #( ls_deal ) TO result.
    ENDLOOP.
  ENDMETHOD.

  METHOD lock.
    " Deliberately empty. The BAPIs run in the DESTINATION 'NONE' session, a different
    " lock owner, and enqueue E_VTBFHA themselves; a lock taken here would make every
    " change and reversal fail against our own foreign lock.
    RETURN.
  ENDMETHOD.

  METHOD has_error.
    rv_error = xsdbool(    line_exists( it_return[ type = 'E' ] )
                        OR line_exists( it_return[ type = 'A' ] ) ).
  ENDMETHOD.

  METHOD rfc_error.
    rs_return = VALUE #( type       = 'E'
                         id         = 'ZFS_TRM_MSG'
                         number     = '020'
                         message_v1 = iv_function
                         message_v2 = iv_text ).
  ENDMETHOD.

  METHOD end_luw.
    DATA ls_return TYPE bapiret2.
    DATA lv_msgtxt TYPE c LENGTH 220.

    IF iv_commit = abap_true.
      CALL FUNCTION 'BAPI_TRANSACTION_COMMIT'
        DESTINATION 'NONE'
        EXPORTING  wait                  = abap_true
        IMPORTING  return                = ls_return
        EXCEPTIONS system_failure        = 1 MESSAGE lv_msgtxt
                   communication_failure = 2 MESSAGE lv_msgtxt
                   OTHERS                = 3.
      IF sy-subrc <> 0.
        APPEND rfc_error( iv_function = 'BAPI_TRANSACTION_COMMIT'
                          iv_text     = lv_msgtxt ) TO rt_return.
      ELSEIF ls_return-type CA 'EA'.
        APPEND ls_return TO rt_return.
      ENDIF.
    ELSE.
      CALL FUNCTION 'BAPI_TRANSACTION_ROLLBACK'
        DESTINATION 'NONE'
        IMPORTING  return                = ls_return
        EXCEPTIONS system_failure        = 1 MESSAGE lv_msgtxt
                   communication_failure = 2 MESSAGE lv_msgtxt
                   OTHERS                = 3.
      IF sy-subrc <> 0.
        APPEND rfc_error( iv_function = 'BAPI_TRANSACTION_ROLLBACK'
                          iv_text     = lv_msgtxt ) TO rt_return.
      ENDIF.
    ENDIF.
  ENDMETHOD.

  METHOD to_message.
    ro_msg = new_message( id       = is_return-id
                          number   = is_return-number
                          severity = SWITCH #( is_return-type
                                               WHEN 'E' OR 'A' THEN if_abap_behv_message=>severity-error
                                               WHEN 'W'        THEN if_abap_behv_message=>severity-warning
                                               WHEN 'I'        THEN if_abap_behv_message=>severity-information
                                               ELSE                 if_abap_behv_message=>severity-success )
                          v1       = is_return-message_v1
                          v2       = is_return-message_v2
                          v3       = is_return-message_v3
                          v4       = is_return-message_v4 ).
  ENDMETHOD.
ENDCLASS.


CLASS lsc_trmfx DEFINITION INHERITING FROM cl_abap_behavior_saver.
  PROTECTED SECTION.
    METHODS save REDEFINITION.
ENDCLASS.


CLASS lsc_trmfx IMPLEMENTATION.
  METHOD save.
    " Deliberately empty: each BAPI call was committed or rolled back in its own
    " DESTINATION 'NONE' session by the handler (L-227). A synchronous RFC is not
    " allowed here in the late save phase.
    RETURN.
  ENDMETHOD.
ENDCLASS.
