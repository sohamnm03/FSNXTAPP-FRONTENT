# TRM letter of credit API (Phase 4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish `ZFS_SB_TRMLC_O4_API`, an OData V4 Web API for letters of credit (product category
850). It covers create/read/update/delete plus the actions `Settle`, `Terminate` and `Present`, over the
released `BAPI_FTR_LC_DEALCREATE` / `DEALCHANGE` / `DEALGET` / `REVERSE` (reason 04) / `SETTLE` /
`TERMINATE` / `PRESENT` BAPIs.

**Architecture:** A clone of the FX transaction API (`ZFS_SB_TRMFX_O4_API`, Phase 2), including its
review fixes:
- one root custom entity with an unmanaged, strict(2), non-draft BDEF
- a query class that lists deals from the released `I_FinancialTransaction` (category 850) and fills each
  page row from `BAPI_FTR_LC_DEALGET`
- a behavior pool that calls each write BAPI `DESTINATION 'NONE'` and commits or rolls back in that
  session (L-227)
- two abstract entities as the parameters of `Terminate` and `Present`

Nothing is built or tested locally.

**Tech Stack:** ABAP RAP (unmanaged custom entity, abstract entities, SAP_BASIS 758), CDS, OData V4, MCP
servers `adt-mcp` / `mcp-abap-abap-adt-api` / `sap-gui`, PowerShell 5.1.

**Spec:** `docs/superpowers/specs/2026-09-25-1410-trm-deal-apis-design.md`. Relevant sections: §3, §6
(API 3), §7 and §9 Phase 4. Phase 3 (FX options) is **on hold** (human, 2026-09-25, L-584).

## Facts established while writing this plan (DS4/100, 2026-09-25, L-585)

- **Test data:** category 850 has exactly 8 deals, all in company code **9999**, all product type
  **38A** "Letter of Credit" / transaction type 100, active (status 0), counterparty `400000000`. Deal
  `9999/0000000100000` is the payload source. Product types 38B SBLC and 38C Bank Guarantee exist in
  TZPAT but have no deals.
- **Activity categories (AT02T, category 850):** 10 Order, 15 Order Expiration, 20 Contract,
  21 Rollover, 30 Contract Settlement, 31 Rollover Settlement, 80 Termination, 90 Termination
  Settlement. So expect **20** after create, **30** after Settle and **80** after Terminate.
- **BAPI signatures (FM sources):**
  - **`DEALCREATE`:** `LETTEROFCREDIT` / `LETTEROFCREDITX` (`BAPI_FTR_CREATE_LC(X)`),
    `GENERALCONTRACTDATA(X)`; all tables optional. Exports `COMPANYCODE`, `FINANCIALTRANSACTION`.
  - **`DEALCHANGE`:** `COMPANYCODE`, `FINANCIALTRANSACTION`, `LETTEROFCREDIT(X)`
    (`BAPI_FTR_CHANGE_LC(X)`), `GENERALCONTRACTDATA(X)`. Non-optional tables: `SALES_PURCHASE_ORDER`,
    `LONG_TEXT`, `NOMINATED_BANK`, `DOCUMENT`, `PRESENTATION(X)`, `PRESENTATION_INVOICE`,
    `PRESENTATION_FLOW`, `PAYMENTDETAIL(X)`, `ADDFLOW(X)`. They are passed empty; the blank
    complete-indicators mean "no change" (L-566).
  - **`DEALGET`:** `RETURNLETTEROFCREDIT` (`BAPI_FTR_GETDETAIL_LC`), `RETURNGENERALCONTRACTDATA`, and
    the tables above (plus the optional `CASHCOLLATERAL`, `CONDITION`, `SINGLEDATE`).
  - **`REVERSE`:** `COMPANYCODE`, `FINANCIALTRANSACTION`, `REVERSALREASON`. **`SETTLE`:** keys only.
  - **`TERMINATE`:** `TERMINATE_DATE` (`BAPI_FTR_CHANGE_LC-TERMINATE_DATE`, DATS),
    `TERMINATE_DATE_INCLUSIVE` (`END_TERM_INCLUSIVE`, CHAR1).
  - **`PRESENT`:** `ACTION_TYPE` (`FTR_PRESENT_ACTYPE`, CHAR 20; values CREA Create, CHGE Change,
    DELE Delete, ACCP Accept, REJE Reject, ACPS Accept Settle, SETT Settle, SEND Send to bank,
    SDRA Set to draft, RVER Reverse), tables `PRESENTATION` / `PRESENTATIONX` / `INVOICE` / `FLOW`.
    It refuses an initial `ACTION_TYPE` (FTR_TF 002) and an empty `PRESENTATION` (FTR_TF 003).
- `BAPI_FTR_CREATE_LC`, `BAPI_FTR_CHANGE_LC` and `BAPI_FTR_GETDETAIL_LC` use the **same component
  names**; change and get add `ROLL_OVER`. The X structures mirror them one-to-one.
- **Conversion exits:** the only exit on the elements used here is ALPHA, on the `BU_PARTNER`-based
  applicant/beneficiary/bank elements. ALPHA is accepted by OData V4; EXCRT would not be (L-575).
- **Non-FX keys:** by L-583, the FTR BAPIs refuse a key of another product category themselves. This
  is re-probed here for LC (check `W12`).

## Deviations from the spec for the human to approve

1. **Presentation items:** after `Present CREA` the caller needs the new presentation item number to
   act on it (CHGE/ACCP/SETT/RVER). The spec leaves presentations out of the entity. This plan adds
   two **read-only** elements, `LastPresentationItem` and `LastPresentationStatus`, filled from
   DEALGET's `PRESENTATION` table (the highest item), and adds `PresentationItem` to the Present
   parameter.
2. **Extra header elements:** `ValuationClass` and `FlowType`, which the spec's §6 list omits. They
   make LC consistent with the IRATE and FX APIs, and `FLOW_TYPE` is part of both create and change.
3. **`DiscrepancyCurrency`** in the Present parameter, next to the spec's `DiscrepancyAmount`.
4. **Review fixes carried in:**
   - the Settle/Terminate/Present result is appended only when the re-read succeeds (Phase 2 F6)
   - `$orderby` gets the keys as a tie-breaker (F10)
   - message 058 on a commit failure after create (L-584)
   - `mandatory : create` covers every field the BAPI is known to require (F8)

If the human declines 1: remove the two elements, their mapping and the `PresentationItem` parameter
field. Present then only supports CREA.

    settled/terminated/presented deal needs several DELETEs.
  - `DEAL*` BAPIs only (L-581 instruction).

## Review Focus

1. **Present on a new LC:** after `Present CREA` the caller must see which presentation was created
   (`LastPresentationItem` non-empty after the action). A 200 with nothing visible is useless. Pinned by
   check `W5`.
2. **Reversing a deal that has a presentation, a settlement or a termination:** DELETE may need several
   calls, and a presentation may block the contract reversal. The suite must end with every test deal
   at ActiveStatus 3 and report how many DELETEs each took. Pinned by `W10`; its recovery is in
   Task 4 Step 6.
3. **Terminate date round trip:** after `Terminate` the read-only `TerminateDate` equals the date sent,
   and ActivityCategory is 80. Pinned by `W9`.
4. **A create refused by the BAPI** (e.g. no currency) rolls back and answers 4xx **without** 058.
   Pinned by `W1b`.
5. **Writes on a non-LC key** (a reversed FX deal) are refused by the BAPI, and nothing is written.
   Pinned by `W12`.

  if (-not $Pass) { $script:ok = $false }

function Json($r) { if ($r.Content) { try { return $r.Content | ConvertFrom-Json } catch { } } return $null }

    ContractDate = (Get-Date -Format 'yyyy-MM-dd'); StartTerm = (Get-Date -Format 'yyyy-MM-dd')

}

Check 'W11 count grew by the test deals only' ($countAfter -eq $countBefore + $deals.Count) "before $countBefore after $countAfter deals $($deals.Count)"

CLASS zcl_fs_trm_lc_query DEFINITION

  CREATE PUBLIC.

  PUBLIC SECTION.
    INTERFACES if_rap_query_provider.

    TYPES ty_deal   TYPE zfs_ce_trmlctp.

    DATA(lv_order) = build_order_by( io_request->get_sort_elements( ) ).

    DATA(lv_top) = io_request->get_paging( )->get_page_size( ).
    IF lv_top = if_rap_query_paging=>page_size_unlimited.
      lv_top = 0.
    ENDIF.

    " Header fields come from the released I_FinancialTransaction, restricted to
    " product category 850 (letters of credit / guarantees). The CTE renames them to
    " the entity's element names so the OData $filter/$orderby string applies as is.
    TRY.
        IF io_request->is_total_numb_of_rec_requested( ).
          WITH +deals AS (
            SELECT FROM i_financialtransaction
              FIELDS CompanyCode,
                     FinancialTransaction,
                     FinancialInstrumentProductType AS ProductType,
                     FinancialInstrTransactionType  AS TransactionType,
                     Counterparty                   AS Partner,
                     TreasuryValuationClass         AS ValuationClass,
                     Portfolio,
                     TransactionCurrency            AS Currency,
                     TermStartDate                  AS StartTerm,
                     TermEndDate                    AS EndTerm,
                     FinancialInstrumentStatus      AS ActiveStatus
              WHERE FinancialInstrProductCategory = '850' )
          SELECT FROM +deals
            FIELDS COUNT( * )
            WHERE (lv_where)
            INTO @DATA(lv_count).
          io_response->set_total_number_of_records( lv_count ).
        ENDIF.

        IF io_request->is_data_requested( ).
          WITH +deals AS (
            SELECT FROM i_financialtransaction
              FIELDS CompanyCode,
                     FinancialTransaction,
                     FinancialInstrumentProductType AS ProductType,
                     FinancialInstrTransactionType  AS TransactionType,
                     Counterparty                   AS Partner,
                     TreasuryValuationClass         AS ValuationClass,
                     Portfolio,
                     TransactionCurrency            AS Currency,
                     TermStartDate                  AS StartTerm,
                     TermEndDate                    AS EndTerm,
                     FinancialInstrumentStatus      AS ActiveStatus
              WHERE FinancialInstrProductCategory = '850' )
          SELECT FROM +deals
            FIELDS *
            WHERE (lv_where)
            ORDER BY (lv_order)
            INTO CORRESPONDING FIELDS OF TABLE @lt_deals
            OFFSET @lv_offset
            UP TO @lv_top ROWS.
        ENDIF.

      CATCH cx_sy_dynamic_osql_error INTO DATA(lx_sql).
        " A $filter/$orderby on a field that only the BAPI supplies (Amount, LcNumber,
        " parties, ActivityCategory, ...) is not a database column of the CTE.
        RAISE EXCEPTION TYPE cx_rap_query_cond
          EXPORTING previous = lx_sql.
    ENDTRY.

    IF io_request->is_data_requested( ) = abap_false.
      RETURN.
    ENDIF.

    " Enrich each row on the page with the fields only BAPI_FTR_LC_DEALGET returns.
    LOOP AT lt_deals ASSIGNING FIELD-SYMBOL(<ls_deal>).
      read_deal( EXPORTING iv_company_code = <ls_deal>-CompanyCode
                           iv_transaction  = <ls_deal>-FinancialTransaction
                 IMPORTING es_deal         = DATA(ls_detail) ).
      IF ls_detail IS NOT INITIAL.
        <ls_deal> = ls_detail.
      ENDIF.
    ENDLOOP.

    io_response->set_data( lt_deals ).
  ENDMETHOD.

  METHOD build_order_by.
    LOOP AT it_sort INTO DATA(ls_sort).
      rv_order = COND #( WHEN rv_order IS INITIAL
                         THEN |{ ls_sort-element_name }|
                         ELSE |{ rv_order }, { ls_sort-element_name }| ).
      IF ls_sort-descending = abap_true.
        rv_order = |{ rv_order } DESCENDING|.
      ENDIF.
    ENDLOOP.
    " The keys always close the order, so pages stay stable when the caller sorts on a
    " non-unique field (Phase 2 review F10).
    rv_order = COND #( WHEN rv_order IS INITIAL THEN c_key_order
                       ELSE |{ rv_order }, { c_key_order }| ).
  ENDMETHOD.

    IF iv_via_rfc = abap_true.

        IMPORTING  returnletterofcredit      = ls_lc
                   returngeneralcontractdata = ls_general
        TABLES     sales_purchase_order      = lt_so_po
                   long_text                 = lt_longtext
                   nominated_bank            = lt_nomibank
                   document                  = lt_document

                   presentation_invoice      = lt_prs_inv

                   addflow                   = lt_addflow
                   return                    = et_return
        EXCEPTIONS system_failure            = 1 MESSAGE lv_msgtxt
                   communication_failure     = 2 MESSAGE lv_msgtxt
                   OTHERS                    = 3.
      IF sy-subrc <> 0.
        APPEND VALUE #( type       = 'E'
                        id         = 'ZFS_TRM_MSG'
                        number     = '020'
                        message_v1 = 'BAPI_FTR_LC_DEALGET'
                        message_v2 = lv_msgtxt ) TO et_return.
        RETURN.
      ENDIF.
    ELSE.

        EXPORTING companycode               = iv_company_code
                  financialtransaction      = iv_transaction
        IMPORTING returnletterofcredit      = ls_lc

        TABLES    sales_purchase_order      = lt_so_po
                  long_text                 = lt_longtext
                  nominated_bank            = lt_nomibank
                  document                  = lt_document
                  presentation              = lt_present
                  presentation_invoice      = lt_prs_inv
                  presentation_flow         = lt_prs_flow
                  paymentdetail             = lt_paydet
                  addflow                   = lt_addflow
                  return                    = et_return.
    ENDIF.

    IF line_exists( et_return[ type = 'E' ] ) OR line_exists( et_return[ type = 'A' ] ).
      RETURN.
    ENDIF.

    " The newest presentation is the one with the highest item number.
    SORT lt_present BY presentation_item DESCENDING.
    DATA(ls_last) = VALUE bapi_ftr_lc_presentation( lt_present[ 1 ] OPTIONAL ).

    es_deal = VALUE #( CompanyCode            = ls_general-company_code
                       FinancialTransaction   = ls_general-transaction

                       TransactionType        = ls_general-transaction_type

                       EndTerm                = ls_lc-end_term

  ENDMETHOD.

                          iv_text     = lv_msgtxt ) TO rt_return.
      ELSEIF ls_return-type CA 'EA'.
        APPEND ls_return TO rt_return.
      ENDIF.
    ELSE.
      CALL FUNCTION 'BAPI_TRANSACTION_ROLLBACK'
        DESTINATION 'NONE'
        IMPORTING  return                = ls_return
        EXCEPTIONS system_failure        = 1 MESSAGE lv_msgtxt
                   communication_failure = 2 MESSAGE lv_msgtxt
                   OTHERS                = 3.
      IF sy-subrc <> 0.
        APPEND rfc_error( iv_function = 'BAPI_TRANSACTION_ROLLBACK'
                          iv_text     = lv_msgtxt ) TO rt_return.
      ENDIF.
    ENDIF.
  ENDMETHOD.

  METHOD to_message.
    ro_msg = new_message( id       = is_return-id
                          number   = is_return-number
                          severity = SWITCH #( is_return-type
                                               WHEN 'E' OR 'A' THEN if_abap_behv_message=>severity-error
                                               WHEN 'W'        THEN if_abap_behv_message=>severity-warning
                                               WHEN 'I'        THEN if_abap_behv_message=>severity-information
                                               ELSE                 if_abap_behv_message=>severity-success )
                          v1       = is_return-message_v1
                          v2       = is_return-message_v2
                          v3       = is_return-message_v3
                          v4       = is_return-message_v4 ).
  ENDMETHOD.
